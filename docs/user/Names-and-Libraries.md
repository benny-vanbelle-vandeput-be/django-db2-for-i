# Names and libraries

A guide to two IBM i specifics a Django model can control:

- the **system name** (at most 10 characters) of a table, a column or an
  index, the name RPG and CL programs and most IBM i tools use;
- the **library** a table is in, when it is not the library given as `NAME`.

The short reference is in [Configuration](Configuration.md#ibm-i-system-names);
what is not covered is in [Known limitations](Known-Limitations.md#tables-in-another-library).

## Setup

The two `Meta` options, `db_system_name` and `db_library`, need
`"django_db2_for_i"` in `INSTALLED_APPS`, anywhere in the list:

```python
INSTALLED_APPS = [
    ...,
    "django_db2_for_i",  # Meta.db_system_name, Meta.db_library
]
```

Without it, Django refuses them ("'class Meta' got invalid attribute(s)").
Column system names (`db_system_name` on a field) and `SystemNameIndex` work
without it. The [checks](#checks) run either way, with
`manage.py check --database default` and `migrate`.

## System names

### Why

Every table, column and index on IBM i has two names: the **SQL name** Django
uses (up to 128 characters) and a **system name** of at most 10 characters
(letters, digits, `_`). `DSPFD`, `DSPFFD`, `WRKOBJ`, RPG's `DCL-F` and CL
programs see only the system name.

A name of at most 10 characters is its own system name. For a longer one,
IBM i makes one up: `DELIVERY_ADDRESSES` becomes something like `DELIV00001`.
That name depends on what else is in the library, so it can differ between
your test and production systems. Set the system name yourself when programs
outside Django use the table.

### A table, its columns and an index

```python
from django.db import models
from django_db2_for_i.fields import with_system_name
from django_db2_for_i.indexes import SystemNameIndex

# Field types with a db_system_name argument. Define them at module level in
# a module of your own: migrations import them from there.
SystemNameCharField = with_system_name(models.CharField, __name__)


class DeliveryAddress(models.Model):
    customer = models.ForeignKey("Customer", models.CASCADE)
    delivery_address = SystemNameCharField(max_length=100, db_system_name="DLVADDR")
    city = models.CharField(max_length=50)  # CITY is its own system name

    class Meta:
        db_table = "delivery_addresses"
        db_system_name = "DLVADDRS"
        indexes = [
            SystemNameIndex(fields=["city"], name="delivery_city_idx", db_system_name="DLVCITY"),
        ]
```

The migration creates:

```sql
CREATE TABLE "DELIVERY_ADDRESSES" FOR SYSTEM NAME DLVADDRS (
    "ID" INTEGER GENERATED BY DEFAULT AS IDENTITY NOT NULL PRIMARY KEY,
    "CUSTOMER_ID" INTEGER NOT NULL,
    "DELIVERY_ADDRESS" FOR COLUMN DLVADDR NVARCHAR(100) NOT NULL,
    "CITY" NVARCHAR(50) NOT NULL
)
CREATE INDEX "DELIVERY_CITY_IDX" FOR SYSTEM NAME DLVCITY ON "DELIVERY_ADDRESSES" ("CITY")
```

On IBM i, `DSPFD FILE(MYLIB/DLVADDRS)` shows the table and `DSPFFD` the column
`DLVADDR`; an RPG program declares `DCL-F DLVADDRS`.

### Field types with a system name

Django's own fields have no `db_system_name` argument. Two ways to add it,
both with the mixin `django_db2_for_i.fields.SystemNameMixin`:

```python
from django.db import models
from django_db2_for_i.fields import SystemNameMixin, with_system_name


class AddressField(SystemNameMixin, models.CharField):  # a class of your own
    pass


SystemNameIntegerField = with_system_name(models.IntegerField, __name__)  # made for you
```

`with_system_name(field_class, module)` names the new class after the field
(`SystemNameIntegerField`); pass `__name__` so migrations find it in your
module. A field without `db_system_name` behaves as the plain Django field.

### Rules

| What | Where | Rule |
|---|---|---|
| Column | `db_system_name=` on a field with the mixin | Only useful for a column name longer than 10 characters. |
| Table | `Meta.db_system_name` | Only for a `db_table` longer than 10 characters: Db2 for i refuses another system name for a short one (SQL7029). |
| Index | `SystemNameIndex(..., db_system_name=...)` in `Meta.indexes` | Indexes Django names itself (`db_index=True`, foreign keys, `unique=True`) keep the name IBM i makes up. |

- A system name has at most 10 characters: letters, digits or `_`, starting
  with a letter. It is stored in upper case.
- Tables and indexes are both `*FILE` objects: within one library, no two of
  them may have the same system name.
- Unique, check and foreign key constraints are not objects and have no
  system name.

### Changing a system name later

- **Column:** a changed `db_system_name` gives an `AlterField` migration that
  changes nothing in the database: Db2 for i cannot rename a column
  ([Known limitations](Known-Limitations.md#renaming-a-column)).
- **Table:** `makemigrations` does not notice it. Run the `RENAME TABLE`
  yourself
  ([Known limitations](Known-Limitations.md#changing-the-system-name-of-a-table)).
  Renaming the table in Django (`AlterModelTable`) keeps its system name.
- **Index:** the migration drops the index and creates it again with the new
  system name.

## Tables in another library

### Why

A Django project usually has all its tables in one library, the `NAME` of
the database settings. Sometimes a table must be in another one: a library
shared with existing IBM i applications, or one library per business area.

The connection's current schema stays `NAME`; only the models that name
another library use it.

### Two ways to name the library

```python
class Customer(models.Model):
    name = models.CharField(max_length=50)

    class Meta:
        db_library = "SALES"  # the clearer spelling
        db_table = "customers"  # optional: Django's default name otherwise


class Order(models.Model):
    class Meta:
        db_table = 'SALES"."orders'  # Django's own form of a qualified name
```

Both give the same result: when the model class is ready, `db_library` is
turned into `db_table = 'SALES"."customers'`. Use one of the two per model;
naming two different libraries is an error (check E005).

### What the backend writes

Every table, constraint and index name on the table gets the library,
because Db2 for i would otherwise put the name into the `NAME` library. For
`Customer` above and a `DeliveryAddress` with `db_library = "SALES"` and a
unique constraint:

```sql
CREATE TABLE "SALES"."CUSTOMERS" (
    "ID" INTEGER GENERATED BY DEFAULT AS IDENTITY NOT NULL PRIMARY KEY,
    "NAME" NVARCHAR(50) NOT NULL
)
CREATE TABLE "SALES"."DELIVERY_ADDRESSES" FOR SYSTEM NAME DLVADDRS (
    ...,
    CONSTRAINT "SALES"."DELIVERY_CUSTOMER_CITY_UNIQ" UNIQUE ("CUSTOMER_ID", "CITY")
)
ALTER TABLE "SALES"."DELIVERY_ADDRESSES"
    ADD CONSTRAINT "SALES"."DELIVERY_ADDRESSES_CUSTOMER_ID_3EBDC4CD_FK_CUSTOMERS_ID"
    FOREIGN KEY ("CUSTOMER_ID") REFERENCES "SALES"."CUSTOMERS" ("ID")
CREATE INDEX "SALES"."DELIVERY_CITY_IDX" FOR SYSTEM NAME DLVCITY
    ON "SALES"."DELIVERY_ADDRESSES" ("CITY")
```

Queries name the table with its library:

```sql
SELECT "SALES"."DELIVERY_ADDRESSES"."ID", ... FROM "SALES"."DELIVERY_ADDRESSES"
WHERE "SALES"."DELIVERY_ADDRESSES"."CITY" = ?
```

System names and libraries work together, as above: a system name must be
unique within its own library only.

### Before you migrate

- The library must exist. The backend never creates or drops a library.
- It must be journaled to a `QSQJRN` journal, as the `NAME` library: Django
  uses commitment control, which needs journaled tables
  ([IBM i requirements](IBM-i-Requirements.md)). A library made with
  `CREATE SCHEMA` has one; one made with `CRTLIB` needs `STRJRNLIB`.
- The user profile needs the authority to create tables in it, and to use the
  tables, as in `NAME`.

### Renaming and moving

- Renaming the table within its library works (`AlterModelTable` from
  `'SALES"."orders'` to `'SALES"."orders_2026'`).
- **Moving** a table to another library, or between `NAME` and another
  library, is refused with `NotSupportedError`: Db2 for i's `RENAME TABLE`
  keeps a table in its library. Move it yourself (for example with
  `CRTDUPOBJ`, or a new table and `INSERT ... SELECT`), then change the model.
- `makemigrations` does not notice a change of `Meta.db_library` alone.

### Tests and other commands

- `inspectdb`, `introspection.get_table_list()`, `flush` (and so Django's
  `TransactionTestCase`) and check W001 cover only the `NAME` library.
- Django's test run creates the table in the library the model names, not in
  a test library: run tests against a system where that library holds only
  test data, or point the model at a test library in your test settings.
- Database-level `on_delete` (`DB_CASCADE`, `DB_SET_NULL`) fails between
  tables in libraries with different journals; Django's `CASCADE` and
  `SET_NULL` work.

## Checks

`manage.py check --database default` (and `migrate`) reports:

| Check | Meaning |
|---|---|
| `django_db2_for_i.E001` | A column system name that is not valid. |
| `django_db2_for_i.E002` | Two columns of one table with the same system name (a short column name counts as its own system name). |
| `django_db2_for_i.E003` | A table or index system name that is not valid, or one given for a name of at most 10 characters. |
| `django_db2_for_i.E004` | Two tables or indexes with the same system name in one library. |
| `django_db2_for_i.E005` | A `db_library` that is not a valid library name, or a model that names two different libraries. |

## Common errors

| Error | Cause |
|---|---|
| SQL7029 | A system name for a table name of at most 10 characters (E003 reports it first). |
| SQL0601 | A table or index with that system name exists in the library already (E004 reports the ones in your models). |
| SQL0612 | Two columns with the same system name (E002). |
| SQL0204 on a table in another library | The library or the table does not exist, or the model names the wrong library. |
| SQL7008 on a table in another library | The library is not journaled: see [IBM i requirements](IBM-i-Requirements.md). |
| `NotSupportedError` "...RENAME TABLE on Db2 for i keeps a table in its library." | A migration moves a table between libraries; see "Renaming and moving". |

More errors by SQLCODE are in [Troubleshooting](Troubleshooting.md).
