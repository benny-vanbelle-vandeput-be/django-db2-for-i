An insert repeated on the same connection after a migration widened a column was refused (`HY019`, or `22001` for a longer string). The first prepare of a `SELECT ... FROM FINAL TABLE` statement fixes its parameter types on that connection (probe `qtemp_final_table_after_alter`), so the driver layer now sends it as a new statement after a schema change. This came with reading keys from the insert itself, after 0.1.0b1, and was never in a release.
