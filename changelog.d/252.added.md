- IBM i system names for columns (#253): a field type with `django_db2_for_i.fields.SystemNameMixin` (or `with_system_name(models.CharField, __name__)`) takes `db_system_name="DLVADDR"`, which the schema editor writes as `FOR COLUMN DLVADDR` in `CREATE TABLE` and `ADD COLUMN`; it is kept in migrations. Any field with a `db_system_name` attribute counts. Plain fields are unchanged.
- IBM i system names for tables and indexes (#253): with `"django_db2_for_i"` in `INSTALLED_APPS`, `Meta.db_system_name` gives the table its system name (`CREATE TABLE ... FOR SYSTEM NAME`); `django_db2_for_i.indexes.SystemNameIndex(..., db_system_name=...)` in `Meta.indexes` does the same for an index. Both are kept in migrations.
- New system checks: `django_db2_for_i.E001` (an invalid column system name), `E002` (two columns of a table with the same system name), `E003` (an invalid table or index system name, or one for an SQL name of at most 10 characters) and `E004` (two tables or indexes with the same system name). See Configuration, "IBM i system names".
