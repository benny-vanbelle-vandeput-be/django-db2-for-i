- `bulk_create(update_conflicts=True)` does not set the primary keys of the objects (a `MERGE` returns no rows); the same key twice in one `bulk_create()` call with conflict handling raises `IntegrityError`; `ignore_conflicts` matches only unconditional unique keys. Under concurrency, `ignore_conflicts`, `update_conflicts` and `m2m.add()` can raise `IntegrityError` when another job inserts the same key at the same moment (from IBM's documentation, not verified on IBM i). See Known Limitations.
