- `DB_CASCADE` and `DB_SET_NULL` between tables in libraries with different journals: every delete of a parent row fails with SQL7008 (probe `lib_fk_across_journals`). Keep both tables in one journal, or use Django's own `CASCADE` / `SET_NULL`.
- A model whose `db_table` is in another library than `NAME`: unique and check constraints fail like foreign keys (SQL5051), and an index lands in the `NAME` library (probe `lib_other_library`; support is planned in #124).
