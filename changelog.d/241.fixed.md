After a migration that adds a NOT NULL column without a default or narrows a column, the table no longer stays locked for other jobs until the connection closes. The problem exists in 0.1.0b3 and earlier: the IBM i Access ODBC Driver's commit and rollback keep a `LOCK TABLE` lock, so other jobs could neither read nor write the table (SQL0913) until the migrating connection closed. A transaction that took the lock now ends with the SQL statement `COMMIT` or `ROLLBACK`, which releases it (also inside an outer `atomic()`; if the `ROLLBACK` fails, the connection is closed); other transactions still use the driver's commit. Workaround for 0.1.0b3 and earlier: run migrations with `manage.py migrate` (its connection closes when it ends), or call `django.db.connection.close()` after `call_command("migrate")`.
