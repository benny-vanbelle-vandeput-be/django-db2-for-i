- `has_bulk_insert`: `bulk_create()` inserts many rows per statement (multi-row `VALUES`), in batches of at most 16,000 parameter markers and 16,000 rows, half of what Db2 for i takes (probe `qtemp_bulk`), and at most 512 markers for `TextField` and `BinaryField` columns, as a statement with about 1,056 of them is refused (PWS0001, probe `qtemp_bulk_types`).
- `can_return_rows_from_bulk_insert`: `bulk_create()` sets the primary keys and `db_default` values of the created objects, read in input order from `SELECT ... FROM FINAL TABLE (INSERT ...) ORDER BY INPUT SEQUENCE`.
- `supports_default_keyword_in_bulk_insert`: an unset `db_default` field is written as `DEFAULT` in a multi-row insert.
- `supports_ignore_conflicts`, `supports_update_conflicts`, `supports_update_conflicts_with_target`: `bulk_create(ignore_conflicts=True)` and `bulk_create(update_conflicts=True, unique_fields=..., update_fields=...)` work, as a `MERGE` (Db2 for i has no `ON CONFLICT`; probe `qtemp_merge`).
- `supports_partial_indexes`, `supports_functions_in_partial_indexes`: `Index(condition=...)` and `UniqueConstraint(condition=...)` create an index with `WHERE` (a unique one for the constraint), also with functions in the condition.
- `supports_expression_indexes`: indexes and `UniqueConstraint`s on expressions (`Index(Lower("title"))`, `UniqueConstraint(Upper("title"), ...)`); introspection reports an expression key without a column, as Django's other backends do.
- `supports_nullable_unique_constraints`, `supports_partially_nullable_unique_constraints`: a nullable `unique=True` field, `unique_together` and `UniqueConstraint(fields=...)` take several NULLs, also in part of a multi-column key (a Db2 for i `UNIQUE` constraint treats NULLs as distinct; probe `lib_unique_catalog`, #213).
- A `UniqueConstraint` with a `condition` or expressions is created as `CREATE UNIQUE WHERE NOT NULL INDEX`, so its NULLs are distinct as well; a plain unique index would treat them as equal.
- `can_use_chunked_reads`: `QuerySet.iterator()` fetches rows in chunks from an open cursor, also while other statements run and commit on the same connection.
- `update_can_self_select`, `delete_can_self_reference_subquery`: an `update()` or `delete()` whose filter reads the same table runs as one statement, without selecting the keys first.
